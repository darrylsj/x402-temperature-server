# x402 V2 Contract and Migration Policy

This companion repository targets x402 V2. New code, examples, tests, and documentation should not teach the V1 wire contract.

## V2 Wire Contract

A protected endpoint should use the V2 HTTP exchange:

1. The seller returns `402 Payment Required` with a base64-encoded `PaymentRequired` object in `PAYMENT-REQUIRED`.
2. The decoded object has `x402Version: 2`, a resource URL, and one or more payment requirements.
3. Each requirement uses a CAIP-2 network identifier such as `eip155:8453`, a token contract address, and an atomic token amount such as `1000` for 0.001 USDC.
4. The buyer retries with its V2 payment payload in `PAYMENT-SIGNATURE`.
5. A successful seller response includes `PAYMENT-RESPONSE` with the settlement result.

The production seller paths use current V2 SDK middleware rather than constructing payment verification by hand.

## Local Mock Mode

Local mock mode is intentionally separate from the protocol. It uses:

- `x-mock-payment: test-paid`
- `x-mock-payment-verified: true`

Those names make it difficult to mistake a test bypass for a real x402 payment. The tests also prove that the former `X-PAYMENT` shortcut does not unlock a mock-protected endpoint.

## Migration Policy

V1 is not a second product surface in this repository. If an old client must be observed during migration, put translation at a clearly marked edge adapter, measure its use, and give the adapter a removal date. Do not weaken the core seller route, copy V1 headers into new examples, or let a compatibility shim become the permanent contract.

Historical receipts and field notes remain historical evidence. They should not be rewritten to imply that an earlier transaction used a newer protocol version. Current instructions and runnable examples, however, must remain V2-native.

## Review Checklist

Before merging an x402 change, confirm:

- dependencies are on the V2 major line;
- `x402Version` is `2`;
- networks use CAIP-2 identifiers;
- assets are contract addresses rather than the string `USDC`;
- amounts are atomic integers rather than decimal prices;
- canonical V2 headers are used in production code;
- mock-only headers are visibly named as mocks;
- V1 header names appear only in an explicit migration note or negative test.
